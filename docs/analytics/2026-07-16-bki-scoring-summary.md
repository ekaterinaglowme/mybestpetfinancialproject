# Аналитика БКИ: что предсказывает невозврат (2026-07-16)

Датасет: 2 587 850 созревших займов (`loans.status IN ('вернули', 'не вернули')`) с
БКИ-профилем `status = 'ok'` + 442 080 займов группы `no_history`.
**Базовая линия (baseline): 36.6%** невозврата среди одобренных с историей.

Метод: bad rate (доля `не вернули`) по корзинам каждого признака `bki_reports`,
одним запросом (UNION ALL + NTILE-квинтили). SQL — в истории Superset SQL Lab.

## Находки по силе влияния

| Место | Признак | Цифры | Вывод |
|---|---|---|---|
| 1 | Нет кредитной истории (`no_history`) | **51%** vs 36.6% | Худшая группа: 442К займов, 225К дефолтов. Сейчас пропускаются без проверки («нет истории — не отказ») — самая дорогая дыра в правилах |
| 2 | «Кредитный голод» (`inq_90` >= 6) | **44.9%** vs ~29.8% | Ступенька: до 5 запросов в бюро за квартал — ровно, с 6 — взлёт |
| 3 | Скор бюро (`score`) | Q1 (270–590): **42.6%** -> Q5 (744–880): **24.8%** | Монотонно работает; шкала в данных 270–880 |
| 4 | Число просрочек (`n_late` >= 6) | **41%** vs 29.6% | Систематическая недисциплина; таких больше половины выдач (1.36 млн) |
| 5 | Опыт (`n_contracts` 4+) | **26.8%** vs 37.7% | Защитный фактор: опытные возвращают лучше |
| 6 | Глубина просрочки (`max_dpd`) | 29.6% (0) vs 37% (1–5 дн) | Слабый: у одобренных в истории максимум 5 дней (глубокие отсечены действующим правилом) |
| — | Долговая нагрузка (`debt_load_kop`) | ~36.6% во всех квинтилях | Не различает: у большинства долг 0 — в этих данных бесполезен |

## Черновик правил выдачи (бизнес-решение за продуктом)

1. `no_history` — отказ или ограничение (сниженный лимит): самый большой эффект,
   но отсекает ~15% потока.
2. `inq_90 >= 6` — отказ (порог виден в данных явно).
3. `score < ~590` (нижний квинтиль) — отказ.
4. `n_late >= 6` — отказ.

## Ограничения (важно)

- **Пересечение групп:** одномерные срезы; суммарный эффект набора правил считать
  отдельной симуляцией («какой станет bad rate и сколько потока отсечём»).
- **Selection bias:** видим только одобренных. Действующие правила
  (см. `server.py`: возраст, ЧС, текущая просрочка, fail-closed при недоступности
  проверок, активный заём, прошлый невозврат) создают слепые зоны — исходов
  отсечённых групп нет, поэтому правила можно добавлять, но не ослаблять
  на основании этих данных.
- 788 527 профилей `has_writeoff = true` — все без займов (отсечены правилом
  «текущая просрочка»): влияние списания на возврат по данным не измеримо.

## Контекст хранения

Источник признаков — `bki_reports` (5.68 GiB, почти всё — `raw_xml`; заморожена,
запись прекращена). Витрина `bki_features` (миграция `0007_bki_features`) сохраняет
все скоринг-колонки без XML; после её проверки на проде `bki_reports` подлежит
удалению отдельной миграцией (вернёт ~5.7 GiB диска).
